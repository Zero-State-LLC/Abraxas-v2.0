# AAL-Viz Visual Asset Gap Inventory 001

**Status:** BUILD SPEC READY  
**Owner:** Applied Alchemy Labs  
**Producer target:** Grok Build  
**Authority:** Projection and visual communication only  
**Production implication:** None  
**Last updated:** 2026-07-25

## Purpose

Define the missing authored visual asset system required to turn AAL-Viz from a panel-rich, CSS-led operator console into a coherent production-grade visual cognition layer. This document governs asset scope, naming, batching, accessibility, and integration. It does not authorize runtime mutation, forecast routing, canon mutation, external production deployment, or the fabrication of live data.

## Current determination

AAL-Viz already has substantial functional UI coverage and deterministic procedural rendering. The missing layer is a unified authored visual language: identity, authority glyphs, activation symbols, rune graphics, subsystem marks, graph primitives, empty/error states, accessibility variants, motion primitives, documentation diagrams, and export templates.

Charts, live topology, metrics, graph coordinates, heat maps, timelines, scores, packet contents, and runtime state must remain code/data-generated. Grok Build should create reusable visual primitives and templates, not baked fake dashboards.

## Priority legend

- **P0:** foundation required before broad visual production

## Grok Build production batches

### Batch 0 — Visual foundation

Produce identity, authority glyphs, activation symbols, navigation icons, core subsystem glyphs, graph primitives, manifest, naming standard, and QA documents. Target approximately 120–150 authored source assets including variants.

### Batch 1 — Runtime-console completeness

Produce empty/error states, workflow symbols, metric annotations, Signal Weather family, panel treatments, and accessibility patterns.

### Batch 2 — Symbolic operating language

Produce the full AAL-Viz rune family, shared visible ABX runes, animated rune paths, and subsystem marks.

### Batch 3 — Documentation and communication

Produce architecture diagrams, infographic templates, report assets, README imagery, and Notion covers.

### Batch 4 — Motion and presentation

Produce deterministic motion primitives, spatial fields, responsive/PWA assets, and presentation derivatives.

## Do not create as static assets

The following remain procedural and data-driven:

- charts and graph layouts
- topology coordinates and edges
- heat maps and timelines
- progress rings and metric values
- confidence intervals and live clusters
- provider scores and reliability values
- runtime packet and receipt contents
- artifact lineage derived from current data
- live Signal Weather state

## Scale estimate

- Semantic inventory: approximately 575 listed deliverables
- Expected reusable authored masters: approximately 180–240 SVG/design sources
- Export count: larger, generated deterministically from master sources and variants

## Acceptance criteria

1. Every asset has a manifest record.
2. Every status has a non-color representation.
3. Every asset is authority-safe and projection-only unless explicitly marked otherwise.
4. SVGs use consistent viewBoxes and naming.
5. Small-size legibility is reviewed at 16 and 24 px.
6. Motion has reduced-motion equivalents.
7. Concept imagery is labeled and cannot be mistaken for implemented runtime state.
8. No static asset embeds fabricated metrics or live system values.
9. Repository placement and import paths are documented.
10. Visual regression references exist before integration into the live console.
